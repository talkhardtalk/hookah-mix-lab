# Журнал Hookah Mix Lab

## 26 ноября 2026 года · запуск проекта

- При старте в каталоге находился пустой Git-репозиторий без коммитов, журнала и удалённого адреса.
- Сверил исходную коллекцию. В ней 47 позиций и 51 упаковка, включая четыре вкуса с двумя упаковками.
- Пользователь разрешил создать приложение и журнал локально. Отправку на GitHub согласуем отдельно. Для публикации готовим GitHub Actions и GitHub Pages.
- Выбрал статическое клиентское приложение на HTML, CSS и модулях JavaScript. Оно работает без аккаунта, сборки и сервера приложений. Публикация использует только папку `public`.
- Профили вкусов являются ориентировочной моделью. Для названий, из которых нельзя однозначно вывести аромат, сверяю материалы производителей и декларации. Неопределённые данные можно поправить в карточке вкуса. Стартовые остатки в граммах неизвестны.

### Каталог, рецепты и персонализация

- Добавил стабильные ID, вкусовые группы, описание аромата, четыре числовые характеристики и ограничение доли для каждого вкуса. Производителя «Клюквиума» и «Черничного чизкейка» оставил пустым, как в исходном списке. В `README.md` сохранил источники профилей с непрозрачными названиями.
- Составил 200 экспериментальных формул, по 40 в пяти профилях. Задействованы все 47 ингредиентов. Проверка нашла две формулы с одинаковым составом и разными долями. Заменил одну так, чтобы все 200 сочетаний отличались набором ингредиентов.
- Подбор отбирает рецепты по закреплённым вкусам, профилю и остаткам. Генератор использует схемы основы, дополнения и акцента. Для известных остатков проверяется точная масса каждого компонента после округления до 0,1 г.
- Дополнил схемы после проверки всех пар. При начальном каталоге, весе 18 г и профиле «Любой» для 1077 из 1081 пар найдено по восемь вариантов, ещё у одной пары семь вариантов. Три пары из двух концентрированных охлаждающих вкусов оставлены без предложений. Для любого одиночного вкуса в начальной коллекции есть восемь вариантов.
- Фактические оценки хранятся отдельно от экспериментальной базы. Ранжирование учитывает оценки, отметки о сладости и других характеристиках, реакции на ингредиенты, близость пропорций и желание повторить. По итогам первого прогона снизил влияние одной оценки. В статистике вывод о смеси строится на повторных наблюдениях, а явная личная оценка отдельного вкуса отображается сразу при достаточном балле.

### Интерфейс, данные и публикация

- Сделал адаптивный графитовый интерфейс с цветными пропорциями, мобильной навигацией и подтверждением возраста. Реализованы редактирование коллекции и пропорций, свои рецепты, избранное, журнал, статистика, случайный микс и перенос JSON-копии.
- Выделил версионный формат и интерфейс хранения для будущего подключения синхронизации. Снимок рецепта сохраняет название, пропорции и данные ингредиентов после изменений в коллекции.
- Добавил `.github/workflows/pages.yml`. GitHub Actions запускает проверки, затем публикует папку `public` при обновлении ветки по умолчанию или ручном запуске на ней. `actionlint` проверил сценарий локально. Порядок запуска и настройки Pages описан в `README.md`.
- Прошли 9 автоматических тестов Node.js. В Microsoft Edge проверил приложение на 1440 px и в мобильной эмуляции на 390 и 320 px. Пройден путь от выбора двух вкусов и генерации до оценки, перезагрузки, избранного, изменения пропорций, создания рецепта с нуля, изменения остатков и переноса данных в чистый браузер. Отдельно проверил запуск из подпапки, как на GitHub Pages.
- Текущий результат готов к локальному запуску. Для первого развёртывания нужны адрес репозитория и согласование отправки. Удалённый репозиторий пока не задан.
