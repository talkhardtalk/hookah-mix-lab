# Hookah Mix Lab

Личная лаборатория кальянных миксов для совершеннолетних. Русскоязычное статическое приложение с 47 вкусами, 51 упаковкой и 200 стартовыми рецептами.

[Открыть Hookah Mix Lab](https://talkhardtalk.github.io/hookah-mix-lab/)

## Запуск

Из каталога репозитория запусти локальный сервер на Python 3 и открой [приложение](http://127.0.0.1:8018/).

```powershell
python -m http.server 8018 --bind 127.0.0.1 --directory public
```

Автоматические проверки запускаются командой `node --test` с Node.js 24. Для самого сайта достаточно браузера с поддержкой модулей JavaScript и `localStorage`.

## Подбор и оценки

- При добавлении вкуса достаточно названия. Описание помогает предложить вкусовые группы, характеристики и максимальную долю в новом миксе. Дополнительные параметры можно уточнить. По умолчанию вкус добавляется в наличии с одной упаковкой.
- Выбери профиль или закрепи один или два вкуса. Чтобы увидеть следующие сочетания с теми же фильтрами, нажми «Показать ещё» под карточками. В режиме «Только новые идеи» предложения рассчитываются по вкусовым группам и ограничениям долей.
- Для подбора учитываются отметка о наличии и количество упаковок. Доли ингредиентов указаны в процентах.
- Базовые и сгенерированные рецепты экспериментальные. Оцени опробованный микс от одной до пяти звёзд. Средняя оценка привязана к составу и пропорциям.
- Ранжирование учитывает оценки вкусов, пар и близких пропорций. Влияние одиночного наблюдения ограничено. Впечатления из старых отзывов остаются в журнале и продолжают учитываться.
- Чтобы изменить состав или проценты, открой «База рецептов» → «Мои рецепты» → «Изменить рецепт». В редакторе можно выбрать свой, стартовый или избранный рецепт. В истории сохраняется состав на момент оценки, включая позже удалённые вкусы.

«Вся база» содержит 200 стартовых рецептов. Новые сочетания появляются в подборе, а сохраняются через избранное, оценку или свой рецепт. Чтобы сразу проверить новый вкус, закрепи его в подборе. Закончившиеся вкусы исключаются из рекомендаций. Для просмотра выполнимых рецептов в базе включи «Есть в наличии».

## Данные и дальнейшее развитие

Данные хранятся в браузере для адреса сайта. В разделе «Мои предпочтения» можно скачать JSON-копию версии 3 и восстановить её в другом браузере. Приложение поддерживает копии версий 1 и 2. Импорт проверяет формат и запрашивает подтверждение замены. Данные остаются в браузере. После перехода с локального адреса на опубликованный сайт их можно перенести тем же способом.

В `public/assets/storage.mjs` выделен интерфейс хранения и схема резервной копии. У пользовательских записей есть стабильные UUID, у опробованных миксов есть дата и снимок ингредиентов. Это позволяет подключить синхронизацию и общие оценки в отдельном слое. Серверный слой потребует правил доступа, разрешения конфликтов и отдельного согласия на отправку отзывов.

## GitHub Pages

1. Для бесплатного размещения выбери публичный репозиторий GitHub. В **Settings → Pages → Build and deployment → Source** выбери **GitHub Actions**. [Документация GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
2. Отправь проект в репозиторий после согласования. Сценарий `.github/workflows/pages.yml` проверит проект и развернёт `public` при обновлении ветки по умолчанию. Публикацию также можно запустить вручную из **Actions** на этой ветке.
3. Ссылка на итоговый сайт появится в результате задания **Опубликовать сайт**. Все пути к ресурсам относительные, поэтому приложение работает и в подпапке проекта GitHub Pages.

Если GitHub предложит настроить Pages только после первого коммита, выбери **GitHub Actions** после отправки и запусти сценарий вручную.
